# Checklist: Oson invoice (create, status)

Contract: [`../references/invoice/README.md`](../references/invoice/README.md). Mark each
item pass / fail / n.a. and cite the file and line that proves it.

## invoice/create
- [ ] `transaction_id` is generated by you, unique per attempt, stored before the call, and not the bare order id (`oson.unique-transaction-id`).
- [ ] `amount` is in soum (major units), computed from the order total without silent rounding up (`oson.amount-major-units`).
- [ ] `currency` is `UZS`; `phone` is digits only; `lang` is `ru`, `uz` or `en`.
- [ ] `lifetime` comes from configuration and its unit is confirmed with Oson (`oson.lifetime-unit`).
- [ ] `return_url` carries an order reference, and `notify_url` is sent and also set in the cabinet.
- [ ] Success means `status == "REGISTRED"` and a non-empty `pay_url`; `bill_id` is stored as a string next to `transaction_id`.
- [ ] The payer is redirected to the `pay_url` from the reply, never to a URL you build.

## invoice/status
- [ ] Called with the same `merchant_id` and `transaction_id` when the payer returns and before shipping without a verified notification (`oson.status-before-shipping`).
- [ ] The returned `transaction_id` and `bill_id` are matched against the stored invoice.
- [ ] Repeated calls back off; there is no tight polling loop.

## Cancel and refund
- [ ] No code calls an invented cancel or refund endpoint; refunds go through the Oson cabinet or support and are recorded manually (`oson.no-refund-api`).
