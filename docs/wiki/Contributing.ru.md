# Как помочь

[English](Contributing.md) · **Русский** · [Oʻzbekcha](Contributing.uz.md) · [简体中文](Contributing.zh-CN.md)

Исправления, новые продукты и новые провайдеры приветствуются. Полные правила — в
[CONTRIBUTING.md](https://github.com/ansoragroup/uzfintech-skills/blob/main/CONTRIBUTING.md).
Здесь — короткая версия.

## Правила, благодаря которым репозиторий можно публиковать

1. **Своими словами.** Пишите заметки сами. Имена полей, типы, коды, лимиты, URL и
   таймауты — это факты, их можно копировать; абзацы текста вендора — нельзя.
2. **У каждого факта есть источник.** В каждом README указаны страница вендора и дата
   загрузки; в каждой схеме есть `x-uzfintech-source`.
3. **Примеры обезличены.** Плейсхолдеры вроде `<CARD_TOKEN>`, `100001`,
   `+998901234567`, `merchant.example.com`. Никогда не используйте реальные или взятые из
   примеров вендора id, имена или суммы.
4. **Данные песочницы хранятся точно.** Тестовые хосты, карты, OTP-коды, тестовые ПИНФЛ,
   сценарии и примеры payload попадают в `references/sandbox/README.md` ровно в том виде, в
   каком их публикует вендор. Без них интеграцию не протестировать.
5. **Факты жизненного цикла сохраняются.** Сроки, правила отмены и возврата, правила
   повторов и фискальных чеков попадают в `references/lifecycle/README.md` со стабильным ID
   предупреждения.
6. **Никаких коммерческих условий.** Никаких ставок комиссии, долей выплат, тарифов и сроков
   расчётов.
7. **`SKILL.md` остаётся роутером**, не длиннее 180 строк. Подробности — в `references/`.

## Перед тем как открыть PR

```sh
scripts/lint --fix        # copies scripts/shared/*.py into every skill, then checks
scripts/lint              # tools, examples, frontmatter, json, links, scan, i18n, versions, lifecycle
scripts/sync --selftest   # needs PyYAML
```

`scripts/lint` должен напечатать `ok` по каждой проверке. CI запускает те же команды на
каждом PR. Если вы изменили поведение, прогоните соответствующий eval:
`claude plugin eval . --tag <provider>`.

## Как исправить факт

1. Найдите страницу вендора, где сказано иначе, и дайте на неё ссылку в PR.
2. Исправьте вместе README справки, схему, пример и пункт чек-листа.
3. Если `SKILL.md` повторяет этот факт (правила, подводные камни, предупреждения),
   исправьте и там.

## Переводы

README и каждая страница вики есть на английском, русском, узбекском и упрощённом
китайском. Сначала меняйте английскую страницу, потом обновите три перевода в том же PR или
откройте issue, чтобы это сделал носитель языка.

- Никогда не переводите имена API, поля, заголовки, коды, значения enum и ID предупреждений.
- Узбекский пишется латиницей, oʻ и gʻ — через U+02BB (ʻ), а не апостроф.
  Это проверяет `scripts/lint --only i18n`. Пишите живым узбекским, а не дословным
  переводом с русского.
- Китайский — упрощёнными иероглифами, названия продуктов — так, как их пишут вендоры.

## Коммиты и PR

Одна тема на PR. Еженедельный workflow синхронизации сам открывает PR, когда меняется
upstream-спецификация или страница; перед мержем перечитайте отмеченные страницы.
